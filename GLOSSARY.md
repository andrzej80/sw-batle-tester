# Глоссарий

Термины, которыми пользуются код и документы. Устройство — в
[ARCHITECTURE.md](ARCHITECTURE.md), решения — в [docs/adr](docs/adr/README.md).

## Время

| Термин | Что значит |
|---|---|
| **Тик** | один ход симуляции. Тик 1 — выполнение всех команд сценария (установка), ходы юнитов начинаются с тика 2 |
| **Фаза** | часть тика. Их три, по порядку: **Scheduled** — отложенные эффекты этого тика, **Main** — ходы юнитов в порядке создания, **Cleanup** — уборка и проверка конца |
| **Пустой тик** | тик без выполненных действий, отложенных эффектов и удалений юнитов. Пустой тик при пустом `Scheduler` заканчивает симуляцию |
| **Отложенный эффект**, задача `Scheduler` | функция «в тик T выполнить X от источника S». Так работает взрыв Мины в следующем ходу |
| **Лимит тиков** | 30 000; страховка, если правила не остановили симуляцию |

## Юнит

| Термин | Что значит |
|---|---|
| **Юнит** | участник симуляции: `UnitId`, тип, позиция, `occupiesCell`, теги, компоненты и поведение |
| **Компонент** | данные юнита одного типа: характеристика (`Strength`), состояние (`Movement` с очередью маршей) или статус. У юнита по одному компоненту каждого типа |
| **Стат** | числовая характеристика из Features: `Strength`, `Agility`, `Range`, `Power`, `Spirit`. Читается через `stat<T>` в момент действия |
| **Компоненты Core** | `Health` (HP), `Movement` (скорость и марши), статусы. Все необязательны: юнит без `Health` не умирает и не бывает целью урона, без `Movement` статичен |
| **Действие** (`IAction`) | то, что юнит может сделать за ход. `true` — выполнено, `false` — неприменимо и мир не тронут |
| **Поведение** (`behaviour`) | упорядоченный список действий юнита. За ход выполняется первое применимое |
| **`occupiesCell`** | юнит занимает клетку и не пускает в неё других. У Ворона и Мины — `false` |
| **Спецификация юнита** (`HunterSpec`) | параметры юнита на языке фичи (`int64_t`), из них фабрика собирает юнита |
| **`SpawnRequest`** | заявка на спавн: id, позиция, занятость клетки и собранный юнит либо ошибки фабрики |
| **Мёртвый** | юнит с HP ≤ 0. Не действует и не бывает целью, но держит клетку до Cleanup |
| **`requestRemoval`** | удаление юнита не через HP (Мина после взрыва), тоже в Cleanup. Только для юнита без `Health`: юнит с HP уходит только через смерть |

## Воздействия

| Термин | Что значит |
|---|---|
| **`TargetSpec`** | описание воздействия: намерение, операция, теги, дистанция |
| **Намерение** (`Intent`) | `Hostile` (против цели) или `Beneficial` (в её пользу) |
| **Операция** (`Effect`) | `Damage`, `Heal` или `Status` — что меняется у цели |
| **Тег** | открытая метка по имени: способ доставки (`melee`, `ranged`, `area`), тип (`physical`, `fire`), свойство юнита (`flying`) |
| **Правило цели** (`ITargetRule`) | компонент цели, который запрещает воздействие или меняет дистанцию (Ворон: ближний бой запрещён, выстрел на 1 ближе) |
| **Отбор** (`Targeting`) | поиск целей по `TargetSpec` с правилами цели; мёртвых и юнитов без `Health` для урона и лечения не возвращает |
| **`Hit`** | одно применение воздействия: `TargetSpec`, источник, цель, величина. Применяет `Interaction` |
| **Статус** (`Status`) | компонент со сроком действия или бессрочный. Точка расширения для механик, которые меняют не HP, а состояние (флаг, бафф, иммунитет). Класс статуса — `final`. Повторное наложение заменяет старый |
| **`Flying`** | правило цели Ворона: против `Hostile` с тегом `melee` — запрет, с тегом `ranged` — дистанция на 1 ближе с обеих сторон; лечение, баффы и взрыв (`area`) не меняет |
| **`MinorHeal`** | действие Лекаря «Малое исцеление»: `Spirit` HP случайному раненому (HP < max) на дистанции 0..2, кроме себя |
| **`MineFuse`** | действие Мины: юнит с `Health` в радиусе 2 — взвестись и поставить взрыв на следующий тик; взрыв бьёт всех в радиусе 3, публикует `MineExploded` и убирает Мину через `requestRemoval` |
| **Событие фичи** | событие, объявленное в Features и опубликованное через `ctx.publish` (`MineExploded`); в вывод попадает через свой адаптер в `App/Output` |

## Движение

| Термин | Что значит |
|---|---|
| **Марш** | приказ дойти до клетки. Повторный `MARCH` встаёт в очередь; активный — первый в очереди |
| **Шаг** | перемещение в одну из восьми соседних клеток, которая ближе к цели марша и свободна для юнита; сначала прямой, иначе обход |
| **Расстояние** | по Чебышёву: `max(abs(dx), abs(dy))` |

## Сценарий и слои

| Термин | Что значит |
|---|---|
| **Установка** | выполнение команд сценария на тике 1 (`SetupContext`: карта, спавн, марши) |
| **Проход проверки** | первый прогон всех команд на отдельном мире без вывода, чтобы собрать все ошибки |
| **Код ошибки** | строка с пространством имён (`unit.duplicate_id`, `hunter.invalid_range`); фичи добавляют свои без правки Core |
| **Привязка** (binding) | адаптер в `App/Bindings`: `io::`-команда → вызов Core или фабрики юнита |
| **Адаптер вывода** | адаптер в `App/Output`: доменное событие → `io::`-событие для `EventLog` |
| **Саморегистрация** | адаптер регистрирует себя макросом в своём файле (`SW_REGISTER_BINDING`, `SW_REGISTER_OUTPUT`); общего списка нет |
| **Владелец Core** | единственный, кто меняет Core; остальные разработчики работают в Features |
