# 0004. Адаптеры команд и событий регистрируются сами

Статус: принято (T12–T14).

## Контекст

Новые юниты добавляют несколько разработчиков одновременно. Если все адаптеры команд
и событий перечислены в одном файле, каждый новый юнит дописывает туда строку. Это
постоянные merge-конфликты и риск забыть регистрацию.

## Решение

Каждый адаптер регистрируется в своём файле одним макросом в конце:
`SW_REGISTER_BINDING(bindX)` для команды или `SW_REGISTER_OUTPUT(outputX)` для
события. Сами списки — статические переменные внутри функций (`bindingList()`,
`outputList()`). `Application` проходит по ним и заполняет `CommandRegistry` и
`EventBridge`. Устройство механизма — ARCHITECTURE.md, п. 5.4.

## Рассмотренные варианты

- **Явный список регистраций в одном файле App.** Состав игры виден в одном месте,
  глобального состояния нет. Отклонено: конфликты при слиянии остаются, даже если
  держать список отсортированным, и регистрацию легко забыть.
- **Генерация списка в CMake по именам файлов.** Статиков нет. Отклонено: появляется
  соглашение об именах файлов и логика в CMake, которую надо поддерживать.
- **Саморегистрация в самих Features.** Отклонено: Features стали бы зависеть от IO
  (ADR 0002).

## Последствия

Риски и как они закрыты:

| Риск | Решение |
|---|---|
| порядок инициализации статиков между файлами | списки — статические переменные внутри функций |
| линкер выбрасывает «неиспользуемые» файлы со статической регистрацией | `App` собирается OBJECT-библиотекой, никогда не статической; правило записано комментарием в `CMakeLists.txt` |
| порядок регистрации зависит от порядка линковки | `CommandRegistry` хранит команды по имени, `EventBridge` — по типу события; порядок ни на что не влияет |
| две регистрации одной команды или события | ошибка при старте с именем команды или типа события (баг, код выхода 3) |
| глобальное состояние мешает тестам | глобально хранится только список указателей на функции; `CommandRegistry` и `EventBridge` тест может собрать сам |
| забыли зарегистрировать адаптер | команда в сценарии даёт `parse.unknown_command`, событие не выводится; ловится сценарным тестом |

Цена: состав игры не виден в одном файле, а если `App` однажды соберут статической
библиотекой, команды молча пропадут (KNOWN_ISSUES, п. 7).
