# 0007. Механизм в Core — только когда у него есть потребитель

Статус: принято на этапе 2 (T18–T19).

## Контекст

При проектировании в Core заложили механизмы «на вырост»:
- модификаторы удара `IHitModifier` (щит, резист, запрет лечения);
- свойства клеток `IMoveCostModifier` и `IEnterTrigger` (болото, капкан);
- выбор поведения при повторном наложении статуса (`Reapply::Keep`, стаки).

Ни Мечнику с Охотником, ни юнитам из «Планов» они не нужны. Работали они только на
тестовых юнитах, но каждый требовал контракта, тестов и раздела в спецификации.

## Решение

Механизм попадает в Core, только когда им пользуется хотя бы один юнит из задания или
«Планов». Перечисленные механизмы удалены.

Остались механизмы с потребителями:

| Механизм | Потребитель |
|---|---|
| `ITargetRule` | Ворон |
| теги | Ворон (`flying`) |
| `Scheduler` | Мина (взрыв в следующем ходу) |
| `Status` без стаков | точка расширения для механик «не через HP» |
| `ComponentRequirements` | все юниты |

## Рассмотренные варианты

- **Оставить механизмы «на вырост».** Отклонено: новичок читает Core, где заметная
  часть кода не работает ни на один юнит, а обещание расширяемости подтверждено только
  тестами на выдуманных юнитах. Владелец Core поддерживает контракты, которые никто не
  использует.

## Последствия

- Броня, щиты, баффы урона, болото и капкан потребуют правки Core. Как вернуть каждый
  механизм — KNOWN_ISSUES, п. 12.
- Правило для владельца Core записано в `src/Core/README.md`.
