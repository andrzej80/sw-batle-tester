# 0005. Отбор целей и применение воздействий — в Core

Статус: принято (T06).

## Контекст

Удар, выстрел, лечение, взрыв Мины и наложение статуса делают одно и то же: выбирают
цели и что-то с ними делают. Правила цели должны соблюдаться во всех действиях, в том
числе в тех, которые напишут позже:

- Ворона нельзя бить в ближнем бою, а дальность выстрела по нему на 1 меньше;
- Мину нельзя атаковать;
- мёртвый — не цель.

## Решение

- Воздействие описывает `TargetSpec`, где каждая ось задаётся отдельно:
  - **намерение** `Intent` — `Hostile` или `Beneficial`;
  - **операция** `Effect` — `Damage`, `Heal` или `Status`;
  - **теги**: способ доставки (`melee`, `ranged`, `area`) и тип воздействия (`physical`, `fire`…);
  - **дистанция**.
- `Targeting` (Core) отбирает цели: исключает мёртвых и юнитов без `Health` для урона и
  лечения, применяет правила цели (`ITargetRule`) каждого кандидата, проверяет
  дистанцию.
- `Interaction` (Core) применяет воздействие и проверяет цель тем же `canTarget`. Если
  `Hit` собран в обход отбора, это `std::logic_error`.
- Правила цели — компоненты самой цели, их пишут Features. Теги — открытый механизм:
  Core знает только `Tag`/`TagSet`, а сами теги объявляют фичи.

## Рассмотренные варианты

- **Отбор целей в Features, в Core только пространственный запрос «кто рядом».**
  Отклонено: любое действие могло бы искать цели напрямую, и соблюдение правил цели
  держалось бы на дисциплине каждого автора действия и на ревью.
- **Один enum `{Attack, Heal, Buff, Debuff}` вместо двух осей.** Отклонено: правило
  Ворона «запрет только для атак» пришлось бы переписывать при каждом новом значении.
  С отдельной осью `Intent` правило проверяет `Hostile` и не замечает новых операций.

## Последствия

- Новый иммунитет добавляется в цель как правило цели, а код атакующих не меняется.
- Поиск целей перебирает всех юнитов (KNOWN_ISSUES, п. 6). Оптимизировать его можно
  внутри Core, не меняя интерфейс.
- Новая форма запроса (например, линия видимости) — изменение Core через его владельца.
- Что делать с HP — отдельное решение, ADR 0006.
