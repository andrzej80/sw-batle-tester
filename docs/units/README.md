Поведение Башни, Лекаря, Ворона и Мины: команды, проверки, сборка, правила, вывод и
критерии приёмки. Основная [SPECIFICATION.md](../../SPECIFICATION.md) описывает Core, IO,
App и общие детали Features; юниты из «Планов» вынесены сюда, по файлу на юнит, чтобы
разработчики разных юнитов не правили один документ.

приёмки покрыты тестами, взаимодействие юнитов между собой — в

## Общее для всех юнитов

Согласованные решения С1–С6 записаны в файлах юнитов с пометкой «согласовано». Общее:

- **Формат команды** — как у `SPAWN_SWORDSMAN` и `SPAWN_HUNTER`: id, координаты, HP (если
  есть), затем статы в порядке README. Все поля — `uint32_t`, разбор — спец. 8.1.
- **Проверка статов** — `requirePositive`: `unit.invalid_stat` «<поле> must be positive,
  got <значение>», все ошибки одним списком; новых кодов ошибок нет. Проверки спавна
  (карта, id, границы, занятая клетка) — общие, спец. 7.
- **Тип в `UNIT_SPAWNED`** — английское имя юнита: `Tower`, `Healer`, `Raven`, `Mine`.
- **Core не меняется.** Каждый юнит — новые файлы по ARCHITECTURE.md, п. 5.3.
  Единственная правка общих деталей — дистанция у `MeleeAttack` (спец. 9.2, задача T25).
